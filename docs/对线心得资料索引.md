## 显示与更新边界

- 仅在已连接、非观战、非历史模拟的 CLASSIC 五对五对局中使用；必须进入加载/对局阶段、有有效游戏编号、双方共十名不重复玩家、全部英雄已知且各队五个位置唯一齐全。此时只在“我方位置相同的敌方玩家”标题行显示心得入口。
- 判断依据是现有对局数据提供的位置指派；不能保证识别双方实际换线、临时换位或服务器错误指派。资料尚未齐全时等待，不用选人概率或英雄热门分路猜测补齐。
- 对局、英雄、位置、卡片目标变化时关闭旧弹窗；断开连接、回大厅或不满足上述条件时移除入口。现有对局面板在本局结算期间仍属于同一 in-game 查询阶段，可继续阅读，回到非对局阶段后撤下。
- 内容随应用离线打包，不在加载时下载攻略，不写入 LCU/SGP，不加入自动配置或游戏输入。现有英雄图标仍由公共资源组件提供，中文名称和心得不依赖联网取回。
- 中文英雄姓名来自 [Riot Data Dragon 16.18.1 中文英雄清单](https://ddragon.leagueoflegends.com/cdn/16.18.1/data/zh_CN/champion.json) 的 `title` 字段；该中文资源的 `name` 是称号。新英雄没有本地姓名时显示英雄编号；没有心得就明确未收录。
- 按用户要求不做自动抓取更新。英雄重做之外，控制效果、位移、护盾、冷却、射程、兵线及地图机制改动也可能改变结论。修改某英雄时须复查涉及它的两个方向，不能仅因为没有重做就认定永久有效。

## 维护入口

资料位于 `src/renderer-shared/components/ongoing-game-panel/widgets/player-info-card/matchup-tips/`：

- `matchups.json`：`championId + opponentId + position` 是有方向的查找键，`points` 保存中文要点，`sourceId` 对应实际读过的原文记录。同一键只允许一条；反向需要独立来源，不得自动反转。
- `sources.json`：作者、URL、页面版本、核对日期、段落定位与取舍。当前只供维护和数据契约检查，不在对局界面显示。
- [中路覆盖表](中路对线心得覆盖表.md)：记录名单快照和已有方向；统计必须按 `MIDDLE` 过滤，名单外对手不得混入名单内覆盖率。
- `champions.json`：本地中文姓名和 Riot 英雄编号；扩展时核对当期官方资源。
- `model.ts`：完整阵容/阶段守卫与方向查找；`MatchupTipsBadge.vue`：标题行入口与中文弹窗；真实集成点是 `PlayerInfoCardHeader.vue`。
- `model.test.ts`：阶段、完整阵容、唯一对位、正反方向、分路、无收录、Zed 排除、游戏编号与数据来源契约。合成数据验证程序行为，不能证明攻略的实战有效性。
- `MatchupTips.stories.ts`：真实玩家卡片标题组件预览，可切换加载/选人/缺人/缺位置/不同对位/Zed/无资料/断开/退局；`fixtures.ts` 与 `MatchupTipsDemo.vue` 仅供测试及预览，不包含真实账号。

增补顺序：读原文具体对位段落 → 核对英雄与分路、排除旧机制和无条件结论 → 写少量原创中文归纳及来源 → 检查重复方向键和姓名 → 更新本索引与维护手册 → 格式化、运行适当验证并随代码提交。不要通过自动生成所有英雄的笛卡尔积来填满覆盖率。
